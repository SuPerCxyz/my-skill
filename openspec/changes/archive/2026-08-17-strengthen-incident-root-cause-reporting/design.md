## Context

当前在线调查主流程先进入环境并按日志优先顺序排查, 共享报告模板在调查完成后才要求输出证据。模板要求按时间线引用原始日志, 但没有规定发现关键证据时的保全行为。离线分析也复用同一模板, 两份 `report-format.md` 必须保持完全一致。

## Goals / Non-Goals

**Goals:**

- 让报告格式成为调查前的证据收集契约。
- 让关键事件在首次发现时就保留可复核的原始日志。
- 用单独的通俗说明帮助不了解上下文的读者理解结论。
- 用分层根因规则阻止将表层错误误报为根本原因。

**Non-Goals:**

- 不改变环境访问、日志查询优先级或运行时写操作授权。
- 不要求在每次调查中无限追查无法验证的外部原因。
- 不要求默认输出完整调试过程或大段无关日志。

## Decisions

### 以报告格式驱动调查

在 `SKILL.md` 的问题调查流程中增加前置读取和证据保全规则, 而不是只在报告模板中追加提醒。前者约束实际调查时机, 后者约束最终输出, 两者共同防止报告阶段缺少原始证据。

备选方案是在日志指南中单独维护完整调查流程。未采用, 因为根因深度和报告字段同时适用于在线与离线日志, 主流程更适合作为统一入口。

### 使用三层因果模型

将结论明确分为用户现象、直接失败和底层根因。只有能说明直接失败为何发生的机制才是根因; 无法验证时保留证据边界而不是扩大结论。这保留排查的停止条件, 也避免不受控的无限调查。

### 用单独字段提供通俗说明

在第 1 节的 `问题原因` 前增加 `通俗说明`, 而不替换现有标题后的原因概述。标题段用于快速定向, 通俗说明用于解释机制, 详细问题原因保留可审计的时间顺序和因果链。

### 共享模板同时更新

两份 `report-format.md` 以完全相同内容更新, 并同步修订离线分析 playbook 中对模板的摘要。这样在线与离线结论不会有不同的报告契约。

## Risks / Trade-offs

- [更多证据字段增加调查输出负担] → 只保留关键事件的最小必要原始日志和上下文, 不默认保存大段无关日志。
- [底层根因暂时不可验证] → 明确输出直接失败和证据缺口, 不伪造根因结论。
- [通俗说明可能与详细根因重复] → 规定它只概括机制和结果, 不复制时间线或原始日志。

## Migration Plan

1. 更新在线调查流程和日志证据规则。
2. 同步共享报告模板与离线分析说明。
3. 检查两份报告模板完全一致, 验证内部链接和 Markdown 格式。
4. 文档变更不涉及运行时部署或回滚; 如需回退, 恢复本 change 修改的文档即可。
