## Context

离线 skill 的工作流分散在主入口、解压说明、分析 playbook 和跨域矩阵中。共享报告模板已经定义新的前置证据和输出契约, 但主入口仍保留旧字段。解压说明同时存在“覆盖合并”和“跳过已解压目录”两种相反规则。

## Goals / Non-Goals

**Goals:**

- 让主入口成为报告契约和证据收集的统一起点。
- 明确已有输出目录的覆盖式增量合并行为和风险。
- 保留跨域调查能力, 同时让范围由实际证据驱动。
- 消除主入口与共享报告模板的字段和序号差异。

**Non-Goals:**

- 不修改解压脚本的现有实现。
- 不改变共享报告模板或在线环境调查流程。
- 不取消跨域矩阵中的候选日志映射。

## Decisions

### 在 Workflow 前增加 Step 0

主入口先读取 `report-format.md`, 再进入解压和搜索。这样即使 Agent 没有主动读取 playbook, 也能在首次调查动作前获得证据字段和根因边界。

### 保留覆盖式增量合并

按用户选择保留脚本现有语义: 当前 bundle 覆盖同路径文件, 追加新文件并保留本次未包含的旧文件。删除跳过已解压目录的相反规则, 同时明确没有备份和自动回滚。

### 将跨域矩阵改为分层路由

主服务和问题域决定初始范围; request ID、资源标识、组件错误和时间关联决定下一层。系统层和基础设施健康检查只在场景相关或出现信号时执行, 操作历史仅在怀疑人工变更时读取。

### 主入口只摘要模板但不得改变模板

离线 Step 7 同步当前必选字段和根因门禁, 并明确事件标签。共享 `report-format.md` 继续作为唯一完整输出契约, 避免再维护第二份模板。

## Risks / Trade-offs

- [覆盖式合并可能替换已有文件] → 文档明确不备份、不自动回滚, 并要求处理用户选定的 bundle 和输出目录。
- [条件扩展可能漏掉隐藏的上游异常] → 跨域矩阵继续提供候选映射, 无法闭合根因时按关联链扩大范围并记录证据缺口。
- [主入口摘要再次过期] → 摘要只保留关键必选字段和指向共享模板的引用。

## Migration Plan

1. 更新主入口的前置流程、报告字段、根因层级和事件标签。
2. 统一解压说明的覆盖式增量合并语义。
3. 将跨域主规则和固定清单改为条件路由。
4. 执行文档检查、OpenSpec strict validation 和解压脚本回归测试。
