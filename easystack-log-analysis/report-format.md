# Problem Analysis Report Format

问题分析完成后使用本格式输出结论。输出分前后两部分: 前部是核心结论, 独立完整、
可直接对外分享; 后部是详细分析, 放完整证据、排查过程和判断依据, 供本人或深入
排查者查看。前部结尾用桥接行指向后部, 前后内容衔接自然, 不割裂。

## Output Contract 输出约束

- 禁止在问题分析结论中使用 Markdown 表格。
- 结论标题和章节名使用普通文本, 列表使用数字项。
- 只有第 1 至第 6 节的章节号允许使用与列首对齐的裸数字序号 (`1.` 至 `6.`)。
- 章节内子项禁止使用与章节号同列并从 1 重新开始的裸数字序号 (`1.`、`2.`),
  必须使用带前缀标签的计数项 (`对象 1:`、`处理 1:`、`证据 1`、`步骤 1`),
  否则编辑器会把章节号和子项合并成连续有序列表并自动重新编号。
- 结论中的任何一行都不得以 `-`、`#` 或 `$` 开头, fenced code block 内同样适用。
- 命令不带 `$` shell prompt。原始日志或配置行命中禁用前缀时, 在原文前增加
  `原文: `, 不删除或改写原始内容。
- 命令使用 `bash` fenced code block; 日志使用 `text`; 配置使用对应语言标识。
- 标题后必须先输出 `一句话总结`, 只概括已有证据直接支持的问题、原因
  和当前状态; 原因未确认时明确写 `原因暂无法确认`。
- 第 1 节和第 2 节为必选章节, 不得省略。
- 第 3 至第 6 节为可选章节, 仅在有实际内容或确有必要时输出。
- 可选章节不适用时直接省略, 不要输出空标题或用 `无` 占位。
- 事实、根因、影响范围和 `不受影响` 结论必须由本次实际查询、日志核对、
  目标环境验证或受控测试直接支持。
- 结论只适用于已验证的环境、版本、配置、组件、对象和时间窗, 不得外推到
  未验证条件。
- `未查到异常`、`当前状态正常` 和 `未执行测试` 不能证明问题不存在。
- 不输出未经验证的推测、经验性判断和假设。`未确认项与限制` 只记录
  客观验证缺口和所需的最小验证。
- 只保留支持结论的关键日志, 不粘贴大段无关输出。
- 密钥、密码、token 和其他凭据必须脱敏。

## Required Structure 必选结构

以下模板定义第 1 节和第 2 节。尖括号内容应替换为实际信息, 不要原样输出。

第 1 节是核心结论, 面向对外分享, 必须自包含; 关键日志只精简摘录 1 至 2 条最关键的
证据, 保证前部简短。第 2 节是详细分析, 面向深入查看, 放完整证据时间线、排查步骤
和根因确认; 与第 1 节对应的证据采用"摘录在前、完整在后", 其余内容不重复。

````text
问题分析结论

一句话总结: <只概括已验证的故障现象、已确认原因和当前状态; 原因未确认时如实说明>

<用户看到的错误或异常>

当前状态:
<持续异常、间歇性异常、已恢复或待确认>

关键证据:

证据 1
来源: <pod、服务、节点、日志文件或命令>
时间: <日志时间或检查时间>
对象: <UUID、pod 名称或其他关联对象>

```text
<支撑直接原因的 1 至 2 条最关键日志, 精简摘录>
```

证据 2

<实际验证的环境、版本、配置、组件、对象和时间窗>
````

## Optional Structure 可选结构

第 3 至第 6 节按问题实际情况选择。需要输出时保持以下顺序; 不需要时省略整节。

````text
3. 影响分析

已确认受影响:

对象 1: <受影响对象>

已确认不受影响:

对象 1: <经目标条件测试或验证后确认不受影响的对象>

未验证范围:

对象 1: <还未执行目标条件验证的对象, 不宣称其受影响或不受影响>

4. 处理建议

立即处理:

处理 1: <当前建议执行的操作>
处理 2: <后续操作>

长期改进:

改进 1: <配置、代码、监控或流程改进建议>

5. 验证方式

验证步骤 1

验证目标: <需要确认什么>

```bash
<验证命令>
```

预期结果:
<正常情况下应看到什么>

实际结果:
<已经执行时填写实际结果; 未执行时明确写 `未执行`>

6. 未确认项与限制

未确认项:

事项 1: <仍需确认的信息>

排查限制:

限制 1: <权限、日志缺失、时间范围或环境访问限制>

下一步:

下一步 1: <继续排查所需的最小动作>
````

## Selection Rules 章节选择规则

- 第 1 节和第 2 节必选。第 1 节关键证据只摘录 1 至 2 条最关键日志, 保证前部简短
  可分享; 第 2 节证据细节放完整日志和时间线, 供深入查看。
- 第 1 节末尾必须输出桥接行, 让前部自包含的同时提示后文继续位置, 前后不割裂。
- 第 3 至第 6 节为可选章节:
  - 只有需要明确故障边界时才输出第 3 节。
  - 只有用户需要修复、缓解或长期改进方案时才输出第 4 节。
  - 只有存在可执行验证动作或需要记录验证结果时才输出第 5 节。
  - 只有结论仍有不确定性、排查受限或需要继续调查时才输出第 6 节。
- `一句话总结` 始终必选, 必须是一个完整句子, 不拆成列表或多行字段。
- 输出前为一句话总结、根因结论和影响范围逐项反查证据。无法指向实际
  日志、命令、配置或测试结果的内容必须删除或降级为未确认项。
- 简单问题也必须保留第 1 节和第 2 节, 但每节可以简洁表达。
- 第 1 节关键证据与第 2 节证据细节允许摘录/完整对应, 其余内容不得重复。
- 输出前逐行检查禁用前缀; 发现行首为 `-`、`#` 或 `$` 时改用数字项、普通文本
  章节名、裸命令或 `原文: ` 前缀。
- 输出前检查序号冲突: 任何行首裸数字序号只能出现在第 1 至第 6 节章节号位置,
  子项一律使用 `对象 1:`、`处理 1:`、`改进 1:`、`事项 1:`、`限制 1:`、
  `下一步 1:`、`证据 1`、`步骤 1` 等带标签的计数项, 不得重新从 1 裸编号。
