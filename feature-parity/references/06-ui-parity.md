# UI Parity

Use with functional verification for UI features.

## Behavior before pixels
Verify route/navigation entry, visibility/permission/flag conditions, enabled/disabled rules, loading/empty/error/success states, validation, modal/drawer/popover lifecycle, update semantics, reload persistence, keyboard/focus/accessibility when material, and responsive/overflow behavior.

## Visual dimensions
When visual parity is requested compare layout hierarchy/spacing, typography and wrapping, control dimensions/alignment, iconography, borders/radius/shadows, state emphasis, responsive behavior, density, and empty/loading/error presentation.

Prefer controlled-viewport screenshots and image diff when tooling permits. Visual similarity never substitutes for interaction/state parity.

## Evidence
Record route/component evidence plus runnable scenario and screenshots/diffs when available. A screenshot alone does not prove interaction parity.
