# Pre-Commit Gate 通用提交前门禁

## 检查清单

在生成提交信息、commit、amend、`git review` 或 push 前, 必须检查:

1. 当前路径是否位于 Git 仓库中
2. Git 仓库根目录是否正确
3. 当前分支是否正确
4. 当前工作目录是否与用户任务一致
5. 工作区有哪些已修改文件
6. 哪些文件已经 staged
7. 哪些文件尚未跟踪
8. 是否存在与本次任务无关的修改
9. 是否存在应提交但尚未跟踪的文件
10. 是否包含日志、缓存、构建产物或临时文件
11. 是否包含编辑器、调试或测试产生的无关文件
12. 是否意外修改根配置、CI、依赖或环境模板
13. 是否包含密码、Token、API Key、私钥或其他敏感信息
14. staged diff 是否只包含本次提交范围
15. 实际改动是否符合用户已确认的需求
16. 相关测试或定向验证是否真实执行
17. 是否存在失败测试、未验证项或已知风险
18. 当前改动应创建新提交还是更新已有提交
19. 提交信息是否准确反映实际 diff

## 常用命令

按需使用以下命令, 只执行完成判断所需的命令:

```bash
git rev-parse --show-toplevel
git branch --show-current
git status --short
git diff --stat
git diff
git diff --cached --stat
git diff --cached
git log -n 20 --format='%h %s'
```

## 暂存规则

不得因为用户只说"提交一下"就直接执行 `git add .`。必须先检查改动范围, 只暂存
属于本次逻辑提交的文件。优先使用明确文件路径暂存。

## 诚实报告

不得虚构已执行命令、退出码、测试结果、commit 结果、push 结果、Gerrit Change
状态、Patch Set 编号或 `git review` 上传结果。关键验证无法执行时, 必须明确说明
原因。没有验证证据时, 不得声称"测试已经通过"、"可以合并"、"已经完整交付"或
"所有功能均已完成"。

## 验证门禁

本 skill 包含提交阶段的质量门禁, 但不重新实现完整测试工作流。提交前至少检查:

- 与本次修改直接相关的测试是否执行
- 是否需要运行 lint
- 是否需要运行类型检查
- 是否需要运行构建
- 是否存在仓库规定的强制验证
- 是否有失败测试
- 是否有因环境限制无法执行的验证
- 是否存在已知回归风险

测试失败时不得声称验证通过、不隐藏失败, 应分析失败是否由本次修改导致。未经
用户明确要求, 不得跳过关键失败继续远程提交。关键验证无法运行时, 说明具体
原因和已经执行的替代验证, 明确剩余风险并降低完成度表述。

## 安全规则

不得执行: 无差别 `git add .`、提交明显无关文件、提交密钥或凭证、直接修改
`.git` 内部文件、`git reset --hard`、`git clean -fd`、未经授权 rebase、
未经授权 force push、未经授权 merge、未经授权删除分支、未经授权 abandon 或
删除 Gerrit Change、为清理工作区而删除用户修改、虚构 Change / Patch Set /
commit / 测试结果。

发现疑似密钥时: 不要在回复中完整复述, 停止将相关文件加入提交, 明确报告
敏感信息风险。
